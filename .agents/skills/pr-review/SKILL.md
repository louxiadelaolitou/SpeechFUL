# PR-review

对指定变更给出有证据、可执行的审查结论。默认只审查；保留现有工作区，不修改源码、提交代码、发布 GitHub 评论或 Review、合并或部署。外部写入须有对应授权，调用本技能本身不构成授权。必要验证可使用隔离的临时环境。

## 确认范围与依据

- 从用户请求和仓库上下文确定 PR 或分支；无法唯一确定时先询问，不猜测审查对象。
- 阅读适用的 AGENTS.md、CONTRIBUTING.md、当前任务记录、PR 描述及相关模块文档。按已确认需求和验收边界审查，现有实现与历史文档不能代替本次需求确认。
- 业务含义存在多种合理解释时，遵循仓库的澄清流程；若要求使用 grill-with-docs，则按要求使用，不可用时说明限制。继续不依赖该取舍的检查，将未决事项与已确认缺陷区分。

## 固定版本与检查合并兼容性

- 核对仓库、源分支与目标分支，记录源 head SHA、目标分支 SHA、merge-base；确认实际读取的代码对应这些版本。
- 获取完整变更清单与差异，追踪必要调用链。明确说明截断、不可访问或未覆盖的部分。
- 分别检查 merge-base 到源 head 的功能变更，以及目标分支在此期间的相关修改。重点检查基于版本1开发、合并时目标已到版本2的相互影响。
- 检查这组源与目标版本形成的实际合并候选代码，并按影响完成适用验证；记录候选提交或代码树标识及其来源 SHA。没有文本冲突不代表逻辑兼容。存在冲突时报告，不在审查中擅自解决；无法获得候选代码时标记兼容性待验。
- 输出前重新核对远端源与目标 SHA。任一变化，补查新增差异及影响，更新候选代码和必要验证，不机械重跑全部检查。若无法核对或分支持续变化，交付已审版本的结果并注明待复查，不无限追赶。
- 结论只覆盖报告中的版本组合；真正合并前仍需核对版本，发生变化不能直接沿用旧结论。本技能不自动执行合并。

## 审查与举证

按变更风险检查业务正确性、认证授权与资源归属、隐私、数据迁移与一致性、事务和并发、性能、API 与已发布客户端兼容性、部署配置及回滚影响。

在 SpeechFUL 中，按实际影响重点检查匿名身份关联、私信隐私、拉黑与内容治理，以及 C Safety Gate 最终业务事务检查；其他 Gate、平台与生产验收分别判断，不互相替代。不预设拉黑等业务的产品语义。

- 优先报告本次新增或加剧的问题；相关历史问题单独注明，不扩展为全仓库整改。
- 每个缺陷给出触发条件、预期行为依据、实际代码路径、可观察影响和修改方向，并定位到审查版本的具体文件与最小必要行范围，优先关联变更行。
- 检查其他层是否已有保护，避免局部误判。合并同一根因的重复发现；不因个人偏好、方法长度或抽象最佳实践凑问题。
- 证据不足的疑点列为待确认事项。按实际影响、范围和紧迫性定级：P0 为需立即处理的严重问题；P1 为高优先级问题；P2 为一般需修复问题；P3 为低优先级改进。另行说明是否阻塞合并，不按问题类别机械定级。

## 验证与交付

检查关键正常、异常、权限和并发场景的测试覆盖。可以运行符合仓库规则的现有测试；需要改源码才能验证时描述方案，不直接修复。仅使用明确隔离的测试资源，不操作正式数据。

区分静态分析、实际执行、CI、真实数据库及设备验证。证据绑定 SHA 或候选代码树，记录必要的环境、命令和结果，使用 PASS / FAIL / BLOCKED / SKIP / NOT_RUN。CI 全绿不能替代业务验收，未执行不得写成通过。

报告保持简洁，按以下顺序输出：

1. **已确认问题**：按 P0–P3 排序；每项包含位置、触发条件、依据、影响、修改建议及是否阻塞合并。无可证实问题就明确说明，不强行填满等级。
2. **待确认事项与验证缺口**：给出具体缺失场景和未覆盖范围。
3. **版本、验证与建议结论**：列出审查版本及必要证据，建议 Approve / Request changes / Comment 并说明理由。关键证据不足时不给无条件 Approve；存在已证实的阻塞缺陷时建议 Request changes。

建议结论不代表 GitHub 成员批准、合并授权或发布验收。只读审查无需新建仓库任务记录，报告默认直接交付在当前对话中。
